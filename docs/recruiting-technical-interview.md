# 기술진단 신입 면접 연습 — 원본 증거 기반

이 문서의 답변은 **연습용 초안**이다. 면접 전 각 링크의 실제 수집·테스트 자료와 본인이 수행한 범위를 확인한 뒤 말해야 한다.

## 자기 프로젝트 40초 요약

"초기 팀 스캐너에서 서비스·버전 식별과 위험도 검토를 수행했고, 이후 개인적으로 서버·DB·WEB/WAS·보안장비 등의 설정 진단 기능을 확장했습니다. 격리 LAB에서 설정과 실제 응답을 수집해 점검 기준과 대조했고, 일부 항목은 개선 후 동일 환경에서 재점검했습니다. 수집 오류와 미검증 상태를 임의로 양호 처리하지 않도록 진단 상태를 분리했습니다. 고객사 수행이 아닌 자체 실습입니다."

## 질문·핵심 답변

1. **포트가 열려 있으면 취약합니까?** 아니요. 서비스·버전, 설정, 인증, 접근통제와 실제 영향 조건을 확인해야 합니다.
2. **CVE 버전 일치가 취약 확정입니까?** 아닙니다. 배포 패치(backport), 취약 기능 사용 여부, 영향 조건과 벤더 권고를 추가 확인합니다.
3. **TCP connection refused와 timeout의 차이는?** 거부 응답은 연결 거절의 관찰이고, timeout은 네트워크·필터·손실·대상 이상 등 복수 원인이 있습니다. timeout만으로 closed/안전을 확정하지 않습니다.
4. **NEEDS_REVIEW와 ERROR의 차이는?** 전자는 판단 근거 부족·추가 검토 필요, 후자는 수집/실행 실패입니다. 일부 점검에는 NOT_TESTED도 별도로 둡니다.
5. **MySQL 권한 진단에서 무엇을 확인했습니까?** 계정, 정적/동적 권한, 역할·프록시 상속, Host/네트워크 제한과 실제 허용 SELECT를 비교했습니다. 범위는 격리 LAB입니다.
6. **권한 제거 후 DB 서비스 장애를 어떻게 막습니까?** 필요 쿼리와 계정 사용처 확인, 별도 테스트, 최소한의 변경, 정상 기능·권한 재점검과 원복계획을 검토합니다. 실제 고객 업무 협의 수행은 아닙니다.
7. **Nginx에서 autoindex off만 보면 됩니까?** 아닙니다. 유효 설정, 실제 배포 파일, HTTP 요청·응답을 함께 확인합니다.
8. **KISA 가이드 항목 PASS이면 인증 적합입니까?** 아닙니다. 선택 항목과 LAB 범위에 한정된 결과이며, 실제 조직관리·전체 시스템·정기 운영 통제를 뜻하지 않습니다.
9. **OPNsense S-06을 왜 완전 PASS라고 말하지 않습니까?** 사용자 지정 PASS 집계가 있지만 전체 PF/앵커와 비인가 LAN→WAN 관리주소 경로를 확인하지 못했기 때문입니다.
10. **AWS CA-09를 왜 미검증으로 남겼습니까?** SG·NACL 설정을 실제 조회했으나 각 규칙의 업무목적 승인과 정기 검토 이력은 기술적 조회만으로 입증할 수 없기 때문입니다.
11. **설정과 실제 동작 검증을 왜 분리합니까?** 설정은 의도를 나타내지만 실제 적용, 우선순위, 네트워크 경로는 별도 관찰이 필요할 수 있기 때문입니다.
12. **증적 해시가 일치하면 출처가 보증됩니까?** 아니요. 저장된 파일의 동일성 확인에 유용하지만 수집 출처·관찰 완전성 자체를 인증하지는 않습니다.
13. **테스트 1,354건 모두 통과입니까?** 아니요. 기록 시점 1,332건 통과·22건 건너뜀입니다. 이것은 자동 테스트 집계이지 취약점 발견·조치 건수가 아닙니다.
14. **팀과 개인이 각각 무엇을 했습니까?** 초기 팀 스캐너와 개인 후속 설정 진단·재점검을 구분하여 설명합니다. 실제 담당 세부사항은 Notion 프로젝트 역할 표를 우선합니다.
15. **재점검을 무엇으로 입증합니까?** 동일 범위의 설정·HTTP/SQL 응답과 전후 검사 조건, 실행 시각 및 증적 링크를 함께 제시합니다.
16. **모르는 질문이 나오면?** 확인한 사실과 추론을 구분하고, 필요한 설정·로그·영향 범위를 설명한 뒤 추가 확인이 필요하다고 답합니다.
