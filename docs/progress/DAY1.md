# 1일차 개발 결과

## 1. 프로젝트 목표

기존 인프라 스캐너의 승인 범위 검증, 포트·서비스 식별, CVE 후보 분석과 위험평가, 증적 및 보고서 기능을 보존하면서 Linux, Windows, DBMS, WEB/WAS, 네트워크·보안장비, 클라우드에 공통으로 사용할 기술적 보안 설정 진단 기능을 추가한다. 1일차 범위는 수집된 값을 오프라인에서 판정하는 엔진과 향후 수집기를 연결할 인터페이스다.

## 2. 수행한 작업

- 기존 프로젝트의 Scope, 포트 스캔, CVE 후보·위험평가, 설정 검증, MySQL 저장 및 JSON/PDF 보고서 흐름을 분석했다. 기존 FTP·SSH·HTTP 검사와 AWS 보안 그룹 검사가 신규 설정 진단과 겹치는 지점을 확인했다.
- GitHub 저장소를 로컬에 클론하고 원격 이름 `origin`과 작업 브랜치 `feature/config-audit-engine`을 확인했다. Windows PowerShell에서 Python 3.12.10 가상환경을 사용했다.
- Windows 호환성 수정 커밋 `f97eb5f`를 확인했다. Nuclei 테스트 픽스처는 LF 바이트를 직접 기록하고, Bash 문법 검사 테스트는 검색한 실행 파일의 절대경로를 사용한다. 사용자가 기존 단위 테스트 330개 통과를 확인했다.
- 관찰값 수집과 판정을 분리하고, 제품·버전 적용성, 증적 참조, 이전 점검 결과 참조를 포함한 공통 결과 모델을 구현했다.
- 수집 오류를 적용성 평가보다 먼저 처리하도록 했다. 버전·조건 함수의 예외는 `ERROR`로 기록하며 예외 원문은 결과에 포함하지 않는다. 로깅과 내보내기에는 허용된 필드만 반환하는 `to_safe_dict()`를 추가했다.

## 4. 판정 상태

| 상태 | 의미 |
|---|---|
| `PASS` | 적용 대상의 실제 관찰값에 대해 규칙이 기준 충족을 명시적으로 반환했다. |
| `FAIL` | 적용 대상의 실제 관찰값에 대해 규칙이 기준 미충족을 명시적으로 반환했다. |
| `NEEDS_REVIEW` | 적용성 판단에 필요한 정보가 부족하거나, 관찰값 해석에 수동 판단이 필요하다. |
| `NOT_APPLICABLE` | 제품 또는 버전 조건에서 적용 제외가 명확하다. |
| `NOT_TESTED` | 적용 대상이지만 관찰값이 수집되지 않았다. |
| `ERROR` | 수집 오류가 전달됐거나 규칙 실행 중 예외가 발생했다. 수집 오류는 적용 제외보다 우선한다. |

미수집 값은 `None`으로 전달한다. 실제로 관찰된 `False`, 숫자 `0`, 빈 문자열은 각 규칙이 의미를 판단한다.

## 5. 검증 결과

표는 사용자가 Windows PowerShell에서 최종 확인한 결과다. 이전 Codex 실행 환경에서는 신규 18개 테스트와 Python 문법 검사가 통과했고, 전체 실행에서는 기존 테스트 5개가 실패했다. Git Bash의 MSYS 초기화에서 접근이 거부된 1건과 루프백 연결 제한이 있었던 로컬 HTTP 테스트 4건이다. 문서 작성 작업에서는 테스트를 다시 실행하지 않았다.

## 6. 미구현 및 미검증 범위

- Ubuntu Linux의 실제 SSH 설정 수집과 MySQL의 실제 SQL 설정 수집
- Suricata, OPNsense, ModSecurity 설정 수집
- 신규 진단 결과의 DB 저장 및 PDF 보고서 연동
- 원격 수집 실행 단계의 Scope 승인 연동
- 실제 장비의 설정 개선 후 재점검

1일차에는 Ubuntu, MySQL, 보안장비를 대상으로 원격 설정을 수집하지 않았다.

## 7. 2일차 계획

1. Ubuntu Linux와 MySQL의 초기 점검 항목을 선정하고, 각 항목의 적용 조건과 기대값을 정의한다.
2. 승인된 테스트 환경에서 대상 자산과 실제 접속 대상을 연결하고, 읽기 전용 Linux 명령과 MySQL 조회를 허용 목록으로 제한한다.
3. 실제 설정값을 수집해 `Observation`으로 전달하고 공통 엔진으로 판정한다.
4. 동일 대상과 점검 항목에서 취약 설정과 개선 설정을 각각 관찰해 판정 및 증적을 비교한다.

## 8. 기술적 한계

- 단위 테스트는 모델과 판정 분기를 검증한다. 실제 장비의 접근 권한, 수집값의 정확성, 제품별 버전 처리와 개선 효과는 승인된 환경에서 별도로 검증해야 한다.
- 로깅과 내보내기에는 `AuditResult.to_safe_dict()`를 사용하고, 반환되는 식별자에 비밀값을 넣지 않는다. `repr=False`는 기본 객체 표현에만 적용되므로 `asdict()`, `vars()` 또는 범용 직렬화로 모델 전체를 출력하면 원본 관찰값이 포함될 수 있다.
- 원격 수집 호출 전에 기존 Scope 정책으로 대상과 범위를 승인하고, 실행할 명령·SQL 및 필요한 권한을 별도로 제한해야 한다. 현재 수집기 인터페이스는 이 검증을 호출자에게 맡긴다.
