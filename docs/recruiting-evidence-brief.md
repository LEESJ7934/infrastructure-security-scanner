# 채용용 기술진단 증거 브리프 (2026-11-23)

> **용도:** 신입 인프라 취약점 진단·정보보호 컨설팅 지원용 1차 읽기 자료. 실무 고객사 진단이 아니라 **승인된 격리 LAB의 자체 실습**이다. 확인하지 못한 범위를 PASS나 실제 운영 이력으로 바꾸지 않는다.

## 30초 설명

초기 팀 서비스·포트 스캐너를 개인 후속 작업으로 확장하여 Linux·Windows·네트워크·MySQL·Nginx/Tomcat·보안장비·AWS의 설정 점검을 수행했다. 일부 항목에서는 설정·실제 응답·접속시험·로그를 대조하고 개선 후 같은 범위를 재점검했다. CVE 버전 일치는 *후보*로, 수집 오류와 미검증 조건은 별도 상태로 유지하도록 구현했다. 실제 고객사 수행·공식 인증 취득은 아니다.

## 대표 사례 1 — MySQL 계정·권한·접근제한 (기술진단)

| 순서 | 기존 증거에서 확인할 내용 |
|---|---|
| 범위 | 일회용 MySQL LAB; D-02, D-04, D-10 선정 점검 |
| 관찰 | 전체 계정·정적/동적 권한·역할/프록시 상속과 클라이언트별 TCP·SELECT 결과 |
| 개선 | 불필요한 계정/과도 권한을 축소하고, 지정 Host·네트워크 경로로 접근 제한 |
| 재점검 | 같은 일회용 서버에서 개선 전후 쿼리·접속을 재수집. 관련 CI에서 D-02·04·10 FAIL→PASS 3개 검증 |
| 한계 | 해당 LAB 기준의 일부 항목. 고객사의 업무상 권한 승인·운영 이력은 검증하지 않음 |

**면접 핵심:** "접속이 안 됐다"는 사실만으로 모든 경로가 차단됐다고 주장하지 않는다. 계정 권한, Host, 통신경로와 허용 클라이언트의 정상 SELECT까지 함께 확인한 이유를 설명한다.

원문: [KISA 선정 최종 대장](kisa-2026-final-scope-result.md) · [WEB/MySQL CI 실행](https://github.com/LEESJ7934/infrastructure-security-scanner/actions/runs/42586652707).

## 대표 사례 2 — Nginx/Tomcat 불필요 파일·정보 노출 (기술진단)

| 순서 | 기존 증거에서 확인할 내용 |
|---|---|
| 범위 | Nginx 및 Tomcat 일회용 WEB/WAS LAB; WEB-04·07·16 |
| 관찰 | 유효 설정·배포 파일 목록·정상/오류/목록/기본 문서 경로의 HTTP 응답 |
| 개선 | 목록화·불필요 배포 파일·오류/버전 정보 노출 관련 설정을 정비 |
| 재점검 | 정상 응답 200, 불필요 경로 404 및 유효 설정/배포 파일 대조. CI에서 WEB-04·07·16 FAIL→PASS 3개 검증 |
| 한계 | 실서비스의 모든 URL·운영환경 전체 점검은 수행하지 않음 |

**면접 핵심:** 설정 파일의 선언만 보는 대신 실제 적용 설정, 파일, HTTP 응답을 교차 확인했다는 점. CI 자동 검증과 개별 수동 LAB 결과를 혼동하지 않는다.

원문: [최종 대장](kisa-2026-final-scope-result.md) · [상세 WEB/WAS 기록](web-was-audit.md).

## 대표 사례 3 — OPNsense 관리 접근통제 (판정 한계 설명)

- **수행:** 지정 인가 관리자 1건 연결 허용, 비인가 출발지 3건 거부와 해당 로그를 수동 대조.
- **확인된 한계:** 전체 PF/앵커 적용 정책과 비인가 LAN→장비 WAN 관리주소 접근경로를 검증하지 못함.
- **정확한 표현:** 선정 16개 집계는 15 PASS / 1 NEEDS_REVIEW이지만, S-06의 PASS는 **사용자 지정 범위 수용**에 포함된 값. 조건을 모두 확인한 실측 PASS는 **14개**이며 CA-09는 NEEDS_REVIEW.
- **금지 표현:** "방화벽의 모든 관리경로를 완벽히 차단했다", "16개 전체 KISA 적합".
- **후속 검증:** 모든 유효 PF 규칙 및 개별 출발지/목적지 경로·로그/카운터를 실제 확보해야 함.

원문: [최종 결과와 필수 조건별 대조](kisa-2026-final-scope-result.md) · [후속 검증](kisa-2026-external-followup.md).

## 기술 판정과 증거 계층

- **실제 LAB 실측:** 승인된 실습 자산에서 설정·응답·패킷·로그를 직접 수집한 결과.
- **수동 확인:** 사용자 화면·콘솔 관찰. 자동 수집 결과와 분리.
- **자동 테스트:** 코드 함수·가상/일회용 LAB의 동작을 검증; 전체 운영보안 적합성의 증명이 아님.
- **모의/합성:** 기능 시연용 데이터이며 실제 보안 사고나 고객사 진단 아님.
- **미검증:** 수집 오류, 근거 미완비, 조직 승인·정기 검토 미증명은 미확인으로 남김.

## 지원서에 사용할 수 있는 표현

> "Python 기반 인프라 취약점 진단 도구를 개인적으로 확장하고, 격리 LAB에서 Linux/MySQL·WEB/WAS의 설정 점검과 개선 전후 재점검을 수행했습니다. 점검 결과는 실제 관찰과 기준에 따라 구분하고, 판정이 어려운 조건은 미검증으로 기록했습니다."

**확인 경계:** 실제 보고서·테스트 실행 여부는 연결된 원본 증거를 기준으로 확인. 이 문서는 기존 원문을 요약하며 새 실측을 수행한 것이 아니다.
