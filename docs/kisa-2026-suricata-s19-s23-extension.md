# KISA 2026 S-19·S-23 확장 평가 — LAB 기능 PASS / KISA 전체 판정 분리

**실측 일자:** 2026-11-16 | **환경:** OPNsense 26.7, Suricata, Hyper-V 격리 LAB  
**사용한 공식 항목:** S-19(상) 이상징후 탐지 모니터링 수행, S-23(중) 유해 트래픽 탐지/차단 정책 설정  
**LAB 기능검증:** **S-19 PASS, S-23 PASS**  
**KISA 항목 전체:** **S-19 NOT_TESTED, S-23 NOT_TESTED** (LAB에서 수행 가능한 조건이 남아 있음)  
**기존 동결 선정:** 16개. 이 문서로 2개를 추가하면 선정 분모는 18개이나, 기존 16개의 과거 기록을 변경하지 않는다.

## 판정 원칙(이 프로젝트의 자체 평가 정책)

| 상태 | 의미 | 예시 |
|---|---|---|
| PASS | **명시된 평가 범위의** 조건을 실제 설정과 시험 결과로 충족 | 실제 IDS Alert 수집, IPS 시험 패킷 차단 및 원복 |
| FAIL | 명시된 기준에 어긋나는 설정 또는 비정상 동작을 실제 확인 | 비인가 접속 성공, 유해 정책 미적용을 실제 확인 |
| NOT_TESTED | LAB에서 검증 가능한 조건이나 **아직 시험하지 않았거나** 증거를 확보하지 못함 | 유해 시그니처 실측, 알림 수신 시험 |
| NEEDS_REVIEW | **실제 고객사 업무·승인·운영 이력 없이는 검증 불가능하거나 실제 조직의 해석이 필요한 조건** | 과거 정기 검토 이력의 진위, 업무상 예외 승인 |
| NOT_APPLICABLE | 정의된 자산·범위와 무관함을 근거로 입증 | 해당 기능 미제공·미사용이 확인되고 적용 대상이 아님 |

이 분류는 본 프로젝트의 **자체 상태 체계**이지 KISA가 위 다섯 가지 상태를 공식 판정 형식으로 정의한 것은 아니다. KISA 가이드는 원칙적으로 양호·취약 판단 기준을 제시하며, 해당 운영환경의 정책과 상황에 따라 평가자가 판단한다.

**중요:** `LAB 기능 PASS`는 특정 기술 동작을 입증한 부분 판정이다. **`KISA 항목 전체 PASS`를 뜻하지 않는다.** 누락된 LAB 검증을 단지 수행하지 않았다는 이유로 `NEEDS_REVIEW`라고 기록하지 않는다.

## S-19: 이상징후 탐지 모니터링 수행

**LAB 기능 PASS — 실제 수행한 시험**

1. Suricata PCAP IDS 모드가 LAN `hn1`에서 실행됨을 프로세스로 확인.
2. `alert ip 10.77.40.20/32 any -> 10.77.40.1/32 any` 시험 규칙 설치, 규칙 로딩 구성·`suricata -T` 정상 종료·`configctl ids reload` 성공 확인.
3. ICMP 시험 패킷 전송 시 정상 통신 유지와 Suricata GUI Alert의 일치 시각·출발지·목적지·SID·프로토콜을 실제 확인.

**KISA 전체 NOT_TESTED — LAB에서 아직 수행 가능한 시험**

- 실제 이상징후로 분류할 비파괴적 시험 패턴에 반응하는 시그니처의 활성/탐지 실측.
- 알림·모니터링 경로의 수신 시험: 예를 들어 담당자용 알림 수신 또는 상시 모니터링 프로세스에서 실시간 인지 가능한지 검증.
- 적용된 인터페이스와 활성 룰셋의 전체 범위 확인.

**실제 조직에서만 판단할 조건(한계점):** 고객사의 상시 관제 담당, 대응 SLA, 실제 에스컬레이션 절차와 장기간 운영 효과. 이것은 LAB에서 수행하지 않은 시험과 구별한다.

## S-23: 유해 트래픽 탐지/차단 정책 설정

**LAB 기능 PASS — 실제 수행한 시험**

1. Suricata Netmap IPS 모드의 실행(`--netmap`) 확인.
2. 제한된 시험 출발지·목적지에 `drop ip 10.77.40.20/32 any -> 10.77.40.1/32 any` 규칙 설치.
3. 같은 네트워크 경로의 Ping 결과를 정책 변경 전 4/4, Drop 적용 후 4/0, Alert 원복 후 4/4, 시험규칙 비활성화 후 4/4로 교차 확인.
4. GUI의 SID·IP·ICMP·Configured action=Drop을 보조 증적으로 확인.

**KISA 전체 NOT_TESTED — LAB에서 아직 수행 가능한 시험**

- 실제 악성·유해 트래픽 **패턴을 구분**하는 활성 시그니처 목록과 해당 액션·인터페이스 검토.
- 비파괴적인 공격 유사 시험 패턴은 차단되지만 정상 패킷은 허용되는지 실측.
- 실습 후 사용자 정의 시험규칙은 비활성화했으므로 **유해 트래픽 방어 정책이 계속 활성화되어 있다는 결론은 내릴 수 없음**.

**실제 조직에서만 판단할 조건(한계점):** 고객사의 위험 수용도, 차단 예외 승인·업무 영향 평가·운영 변경 절차. 이것은 LAB 미시험과 구별한다.

> `drop ip` 규칙은 출발지/목적지만 비교하므로 무해한 Ping도 차단한다. 이를 실제 악성 트래픽 시그니처 검증 결과라고 부풀려 설명하지 않는다.
